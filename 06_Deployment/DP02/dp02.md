## 📌 Day 2 체크포인트 답변 모음

### 섹션 1 체크포인트
1. **FastAPI가 Flask보다 모델 배포에 적합한 이유 세 가지는 무엇입니까?**
   - **자동 데이터 검증**: Pydantic이 내장되어 있어 요청 데이터의 타입과 구조를 모델 진입 전에 자동 검증합니다.
   - **자동 대화형 문서화**: Swagger UI(`/docs`)와 ReDoc이 코드 기반으로 실시간 자동 생성되어 별도 문서 작성 없이 브라우저에서 바로 테스트가 가능합니다.
   - **비동기 지원 (async/await)**: Starlette와 Uvicorn 기반의 비동기 처리를 기본 지원하여 동시 요청 처리 성능이 뛰어납니다.

2. **Uvicorn의 역할은 무엇이며, 왜 FastAPI와 함께 사용합니까?**
   - Uvicorn은 비동기 표준 인터페이스인 ASGI(Asynchronous Server Gateway Interface) 기반의 경량 웹 서버입니다.
   - FastAPI 자체에는 네트워크 소켓을 열고 HTTP 요청을 직접 수신하는 웹 서버 기능이 없으므로, Uvicorn이 앞단에서 HTTP 요청을 받아 FastAPI 애플리케이션으로 전달하는 역할을 합니다.

3. **`@app.get("/health")`에서 `get`과 `"/health"`는 각각 무엇을 의미합니까?**
   - `get`: 클라이언트가 리소스를 조회할 때 사용하는 HTTP 요청 메서드(GET)를 의미합니다.
   - `"/health"`: 해당 함수가 요청을 처리할 URL 경로(Endpoint Path)를 의미합니다.

4. **FastAPI에서 `dict`를 반환하면 어떤 일이 자동으로 일어납니까?**
   - FastAPI의 직렬화 엔진이 Python `dict`를 표준 JSON 문자열로 자동 변환하고, 응답 헤더에 `content-type: application/json`을 설정하여 클라이언트에 전송합니다.

### 섹션 2 체크포인트
1. **`/models/sentiment-v1`에서 `sentiment-v1`은 어떤 종류의 파라미터입니까?**
   - URL 경로 자체에 포함되어 특정 리소스를 고유하게 식별하는 **Path 파라미터**입니다.

2. **`/models?status=running&limit=5`에서 `status`와 `limit`은 어떤 종류의 파라미터입니까?**
   - URL 뒤에 `?key=value` 형태로 전달되어 검색, 필터링, 페이지네이션 조건을 지정하는 **Query 파라미터**입니다.

3. **모델 추론 요청에 Request Body를 사용하는 이유는 무엇입니까?**
   - 추론에 필요한 입력 데이터(이미지 픽셀 리스트, 긴 텍스트 등)는 구조가 복잡하고 용량이 클 수 있어, URL 길이 제한이 없고 다양한 데이터 타입을 안전하게 전달할 수 있는 HTTP 요청 본문(JSON)이 필수적이기 때문입니다.

4. **FastAPI에서 함수의 파라미터가 Path, Query, Body 중 어디서 오는지 어떻게 판별합니까?**
   - URL 경로 데코레이터(`{param}`)에 명시되어 있으면 **Path 파라미터**
   - Pydantic `BaseModel` 상속 타입으로 선언되어 있으면 **Request Body**
   - 그 외 단일 기본 타입(str, int, bool 등)으로 선언되어 있으면 **Query 파라미터**로 자동 판별합니다.

### 섹션 3 체크포인트
1. **FastAPI에서 Swagger UI에 접속하려면 어떤 URL로 이동합니까?**
   - 기본적으로 `http://localhost:8000/docs` 로 접속합니다.

2. **Swagger UI가 코드와 항상 동기화될 수 있는 이유는 무엇입니까?**
   - FastAPI가 엔드포인트 선언, 타입 힌트, docstring, Pydantic 모델을 읽어 `/openapi.json` 스펙을 실시간 동적으로 생성하고, Swagger UI가 이 스펙을 렌더링하기 때문입니다.

3. **Pydantic 모델의 `Field(description=, examples=)`는 Swagger UI의 어디에 반영됩니까?**
   - `description`: Schemas 및 파라미터 목록의 필드 설명 텍스트로 표시됩니다.
   - `examples`: 엔드포인트의 Request Body 기본 입력 폼에 샘플 JSON 값으로 표시됩니다.

4. **Swagger UI와 ReDoc의 핵심 차이는 무엇입니까?**
   - **Swagger UI**: `[Try it out]` 버튼을 통해 브라우저에서 직접 요청을 보내고 응답을 확인할 수 있는 대화형 테스트 도구입니다.
   - **ReDoc**: 테스트 기능은 없지만, 깔끔한 3열 레이아웃으로 API 명세를 열람하는 데 특화된 읽기 전용 문서입니다.

### 섹션 4 체크포인트
1. **`text: str`과 `text: str = "기본값"`의 차이는 무엇입니까?**
   - `text: str`: 기본값이 없는 **필수(Required) 필드**로, 요청에서 누락되면 422 에러가 발생합니다.
   - `text: str = "기본값"`: 클라이언트가 생략할 수 있는 **선택적(Optional) 필드**이며, 생략 시 지정된 기본값이 적용됩니다.

2. **`Field(..., min_length=1, max_length=5000)`에서 `...`은 무엇을 의미합니까?**
   - 해당 필드가 기본값이 없으며 반드시 전달되어야 하는 **필수(Required) 필드**임을 의미합니다.

3. **422 에러 응답에서 `loc` 필드는 어떤 정보를 담고 있습니까?**
   - 에러가 발생한 위치(Location)를 리스트 형태로 나타냅니다. (예: `["body", "text"]` → 요청 본문의 `text` 필드에서 검증 오류 발생)

4. **`response_model`을 지정하면 어떤 이점이 있습니까?**
   - 출력 데이터의 스키마 자동 검증 및 Swagger UI 응답 문서화가 이루어지며, 스키마에 정의되지 않은 민감한 내부 필드가 실수로 클라이언트에 노출되는 것을 자동으로 필터링해 줍니다.

### 섹션 5 체크포인트 (Day 2 최종)
1. **모델을 서버 시작 시 한 번만 로드해야 하는 이유는 무엇입니까?**
   - 모델 파일(가중치)을 디스크에서 메모리로 읽어오는 I/O 및 초기화 연산은 많은 시간이 소요되므로, 매 요청마다 로드하면 응답 시간이 수 초 이상으로 지연되기 때문입니다.

2. **`pixel_values`가 784개가 아닌 요청이 들어오면 어떤 일이 발생합니까? 이를 처리하는 코드를 직접 작성했습니까?**
   - Pydantic 스키마에 `min_length=784, max_length=784` 제약 조건을 지정해두었기 때문에, FastAPI가 함수 진입 전 자동으로 `422 Unprocessable Entity` 에러를 반환합니다. 따라서 별도의 검증 `if`문 코드를 직접 작성하지 않아도 됩니다.

3. **`HTTPException(status_code=503)`은 어떤 상황에서 사용했습니까? 왜 500이 아니라 503입니까?**
   - 모델 파일 로드 실패 등의 이유로 서버가 요청을 처리할 준비가 되지 않았을 때 사용했습니다.
   - `500(Internal Server Error)`은 처리 중 발생한 일반적인 내부 버그를 뜻하지만, `503(Service Unavailable)`은 서비스가 일시적으로 사용 불가능함을 클라이언트에 정확히 알리는 RESTful 규약에 맞는 상태 코드이기 때문입니다.

4. **Swagger UI에서 `PredictRequest`의 `description`과 `examples`가 어디에 표시됩니까?**
   - `description`은 하단 Schemas 섹션의 `PredictRequest` 필드 설명란에 표시되며,
   - `examples`는 `POST /predict` 엔드포인트의 Request body 예시 JSON 영역에 784개의 0.0 리스트로 자동 채워져 표시됩니다.
