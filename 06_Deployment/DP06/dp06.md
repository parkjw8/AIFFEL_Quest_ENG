#  체크포인트 답변

##  1 체크포인트

**Q1. 인증 없는 API가 위험한 이유를 두 가지 이상 설명하세요.**
- 무차별 대량 요청(DDoS)으로 서버가 과부하되어 다운되고 정상 사용자가 서비스를 이용하지 못하게 됩니다.
- 클라우드 환경(AWS, GCP 등)에서 GPU/CPU 리소스 남용으로 과도한 비용이 청구될 수 있습니다.
- 대량의 입력-출력 데이터를 수집하여 모델을 모방/복제하는 모델 도용(Model Stealing) 위험이 있습니다.
- 요청자를 식별할 수 없어 에러 발생 시 원인 추적이나 악의적인 사용자 차단이 불가능합니다.

**Q2. API Key 방식이 ML 추론 API에 적합한 이유는 무엇입니까?**
- 복잡한 사용자 로그인 세션 구현 없이 요청 헤더에 키를 포함하는 것만으로 구현이 간단합니다.
- 발급된 키를 통해 허가된 사용자만 접근하도록 제어하고 사용자별 호출 횟수 및 사용량을 쉽게 추적할 수 있기 때문입니다.

##  2 체크포인트

**Q1. Header(None)에서 None은 어떤 상황에서 x_api_key에 들어갑니까?**
- 클라이언트가 요청을 보낼 때 `X-API-Key` 헤더를 아예 포함하지 않고 보낸 경우 기본값으로 `None`이 들어옵니다.

**Q2. Depends(verify_api_key)를 엔드포인트에 추가하면 요청 처리 흐름이 어떻게 바뀝니까?**
- 엔드포인트 함수가 실행되기 전 `verify_api_key` 함수가 먼저 실행됩니다.
- API Key 검증에 성공하면 사용자 정보(예: `"사용자A"`)가 엔드포인트 파라미터로 주입되어 본문 로직이 실행됩니다.
- 검증에 실패하거나 키가 없으면 `HTTPException(401)`이 발생하여 엔드포인트 본문은 실행되지 않고 즉시 401 응답이 클라이언트에 반환됩니다.

**Q3. 인증 실패 시 반환하는 HTTP 상태 코드 401의 의미는 무엇입니까?**
- `401 Unauthorized`: 클라이언트의 인증 정보가 누락되었거나 유효하지 않아 요청을 처리할 수 없음을 나타냅니다.

##  4 체크포인트

**Q1. UploadFile과 Base64 방식의 핵심 차이는 무엇입니까?**
- **UploadFile**: `multipart/form-data` 형식으로 원본 바이너리 파일을 직접 전송하여 데이터 오버헤드가 없고, Swagger UI에서 파일 선택 UI가 기본 제공됩니다.
- **Base64**: 바이너리 데이터를 텍스트 문자열로 인코딩하여 JSON에 담아 전송하는 방식으로, 인코딩 과정에서 데이터 용량이 약 33% 증가합니다.

**Q2. file.content_type으로 타입을 검증하는 이유는 무엇입니까?**
- `text/plain`과 같이 명백히 이미지가 아닌 잘못된 파일 형식을 1차적으로 빠르게 걸러내기 위해 사용합니다. (단, MIME 타입은 클라이언트에서 위조될 수 있으므로 실제 이미지 디코딩 검증을 병행해야 합니다.)

**Q3. 파일 크기를 제한하지 않으면 어떤 문제가 발생할 수 있습니까?**
- 수백 MB 이상의 대용량 파일이 들어올 경우 서버 메모리나 디스크가 고갈되거나, 전처리 병목으로 인해 서버 전체의 응답 지연 및 다운 현상이 발생할 수 있습니다.

## Day 6 최종 체크포인트

**Q1. API Key 인증이 없으면 어떤 위험이 있습니까? (두 가지 이상)**
- 무차별 호출로 인한 서버 다운, 클라우드 비용 폭탄, 모델 입출력 데이터 탈취를 통한 모델 도용(Model Stealing) 위험, 악의적 사용자 추적 불가.

**Q2. Depends(verify_api_key)는 엔드포인트 실행 전에 어떤 일을 합니까?**
- 요청 헤더의 `X-API-Key`를 읽어 유효성을 먼저 검증하고, 유효하면 사용자 식별 정보를 엔드포인트에 주입하며, 실패 시 401 예외를 던져 엔드포인트 실행을 차단합니다.

**Q3. UploadFile 방식이 Base64보다 편리한 점은 무엇입니까?**
- 별도의 Base64 인코딩/디코딩 변환 작업 없이 원본 파일을 직접 전송하며, Swagger UI에서 파일 첨부 버튼을 자동으로 지원하여 테스트가 편리합니다.

**Q4. 파일 업로드 시 크기 제한을 하지 않으면 어떤 문제가 생깁니까?**
- 과도한 크기의 파일 업로드로 인해 서버 메모리 부족이 발생하고 전처리 지연으로 서버가 다운될 수 있습니다.

**Q5. 이미지를 28x28 그레이스케일로 변환하는 이유는 무엇입니까?**
- 학습된 MNIST 분류 모델의 입력 텐서 규격이 단일 채널(1채널)의 `(1, 28, 28)` 형태에 맞춰져 있기 때문입니다.
